Introduction
Background of the Study

Understanding the challenges that motivated Knowrizon

⚡Traditional classrooms follow a one-size-fits-all approach that fails to accommodate diverse learning needs
⚡Students lack immediate, personalized academic support outside of classroom hours
⚡Manual creation of assessments and study materials is time-intensive for educators
⚡Advances in AI and large language models enable intelligent tutoring systems
⚡Growing need for platforms integrating content processing, tutoring, and assessment
Introduction
Statement of the Problem

The research seeks to address the following questions

01

How can an AI platform provide personalized, context-aware tutoring that adapts to individual student needs?

02

How can automated content processing transform uploaded materials into structured educational resources?

03

How can intelligent assessment generation produce diverse quizzes with immediate explanatory feedback?

04

How can a unified platform integrate AI tutoring, assessment, analytics, and social learning?

Introduction
Objectives of the Study

To develop Knowrizon — an AI-powered adaptive tutoring platform

🎯Design an AI-powered adaptive tutoring system with Socratic questioning and adaptive strategies
🎯Implement automated content processing for PDFs, images, and videos
🎯Develop intelligent quiz generation with concept tagging and explanatory feedback
🎯Create a learning analytics dashboard for progress and performance monitoring
🎯Integrate social learning features — friends, messaging, study groups, voice/video calls
Methodology
Agile Scrum Sprint Framework

Iterative development with continuous feedback and incremental delivery

Why Agile Scrum?
• AI components require iterative prompt engineering
• User features demand continuous usability testing
• Modular system supports parallel sprint development
• Early issue detection through working increments
Structure
• 4 Sprints — 1–2 weeks each
• 12 Features in product backlog
• Sprint Reviews after each iteration
• Retrospectives for improvement

Testing & Retrospective

Continuous evaluation with key findings from each sprint

🧪 Testing Activities
Functionality — End-to-end workflows, API validation

Usability — UI navigation, responsive design, themes

Performance — AI response times, page load optimization

Property-Based — Hypothesis framework for edge cases
🔍 Key Findings
Sprint 1: CORS config required careful setup
Sprint 2: Large PDFs → chunking strategy developed
Sprint 2: Malformed JSON → robust parsing fallback
Sprint 3: Streaming latency → prompt optimization
Sprint 4: In-memory → SQLite → PostgreSQL migration
Deployment
Production Deployment

Serverless architecture on Vercel with Supabase PostgreSQL

🌐
Frontend Delivery
React built with Vite into optimized static assets, served from Vercel's global CDN with code splitting.
⚡
Serverless Backend
Flask deployed as Vercel serverless Python function with 60s max duration for AI endpoints.
🗄️
Database Infrastructure
Production data on PostgreSQL via Supabase with NullPool for serverless environments.
🔒
Security
Credentials managed through Vercel encrypted environment variables — API keys, DB URLs, secrets.
Insights
Lessons Learned

Key insights from the iterative development process

📐
Spec-Driven Development
Clear requirements prevented scope creep throughout all sprints
🔧
Modular Prompts
JSON configs enabled rapid AI behavior iteration without code changes
⚡
SSE Streaming
Dramatically improved perceived AI performance and user wait times
🧪
Property-Based Testing
Hypothesis caught edge cases traditional unit tests missed
📈
Progressive Infrastructure
In-memory → SQLite → PostgreSQL was the right migration path
🤖
Graceful Degradation
Fallback modes kept the system functional when APIs were unavailable
